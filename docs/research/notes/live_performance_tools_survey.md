# Live-performance tools survey: what comparable ecosystems do that g3xn doesn't (feature + automation brainstorm)

Method: five parallel research passes (setlist/band apps + multi-device sync; backing-track rigs; guitar-modeler ecosystems; following teleprompters + rehearsal tooling; show-automation demand + forum wish lists) plus direct checks of the Zoom G3n/G3Xn product page, the v2.0 firmware notes, Python Ableton Link bindings, and spot-fetches of the most load-bearing pages (Helix Stadium Song View, the Neural DSP tuner-MIDI thread, MultiTracks Playback click sections, Stage Traxx network sessions, the 2026 Fader & Knob level-matching guide). Labels on findings: [official-docs] [forum] [review] [article] [paper] [unconfirmed snippet] (= seen only through a search summary; wording and date not verified by opening the page). Reddit refused all fetches, so no Reddit quotes appear.

Effort scale used in Inferences: S = roughly a day or two of daemon/API work; M = about a week; L = multi-week. Value is rated for one guitarist in a pop/rock cover band. Per the project convention, feasibility notes describe daemon/API/MCP-tool/MIDI/audio-feed work; where a new screen would eventually be needed it is only flagged, not designed.

Pedal facts verified for feasibility notes: 150 user patch slots, up to 7 effects/amp models per patch, Auto Save of all patch parameters, 80 s looper, 68 rhythm patterns, a chromatic tuner that can bypass the patch or mute the signal, a 3.5 mm AUX IN that mixes into the outputs, USB Micro-B carrying only USB-MIDI (no 5-pin MIDI, no USB audio listed), no global EQ in the feature list, and the product page lists no setlist or gig features for Guitar Lab (only patch/effect management, backup, clipboard and a news feed) — [Zoom G3n/G3Xn product page](https://zoomcorp.com/en/us/multi-effects/guitar-effects/g3n-g3xn/). Firmware v2.0 added "OutputVP that takes over the volume setting when switching patches" (the note says no more than that) and Guitar Lab 3 support — [Zoom v2.0 notes](https://zoomcorp.com/en/ca/news/firmware-update-v20-zoom-b3n-g3n-and-g3xn). Delay/reverb effects reportedly have a per-effect "Tail" ON/OFF setting (effect sound continues after the effect is switched off), which would be effect-bypass spillover only; nothing found documents tails across a patch change — [Zoom FX list](https://zoomcorp.com/media/documents/E_G5n_G3n_G3Xn_FX-list.pdf.pdf) [unconfirmed snippet].

## Q1. Setlist / band-management apps: what they automate per song, and what users praise or request

### Takeaway
BandHelper is the reference: selecting a song fires MIDI presets (bank/PC, CC, raw hex, MIDI beat clock), previews tempo with a click or visual flash, autoscrolls on a fixed song duration, and computes remaining time and projected end of the show plus set-break countdowns; OnSong adds a scheduled "run sheet" (Moments), section-triggered MIDI during autoscroll, tempo detection from the mic, and song-usage reports; Stage Traxx times lyrics with LRC-style stamps and embeds MIDI at timestamps. What g3xn lacks from this group is set timing, MIDI/OSC out to other gear on song change, song-completion auto-advance, per-member personal versions/notes, and song-usage history. The clearest user pain in the sources is authoring timed changes by hand.

### Inferences
- Idea: set clock and projected end. What: per-song durations (ghost-band length or LRCLIB duration), the measured average gap between songs from past recaps, a set start time, a hard-stop time and break entries; output remaining time, projected end, "N minutes over/under", and a cut/add suggestion; expose as an API field and an MCP tool so "how are we doing on time?" works by voice. Why: BandHelper's projected completion is a core feature; a Setlist Helper reviewer's only complaint is missing set length; bar gigs have hard stops. Effort S–M. Value high. Feasibility: the daemon already timestamps song starts (two-bar tap) and knows the set order; no new hardware.
- Idea: song-completion flow. What: when a song's clock reaches its end (or N s of guitar silence on the audio feed after the end), advance the stage to the next song, surface its tuning/key/tempo, and pre-stage the next patch; only switch the pedal automatically when an explicit setting allows it and the guitar has been silent for N s, with a pause/set-break entry type that stops the flow. Why: BandHelper Song Completion actions and OnSong's 1–30 s auto-advance exist; the Kemper user's "re-send doesn't reset state" complaint argues for re-pushing the planned patch on every song select. Effort S. Value medium-high. Risk: a mis-timed automatic patch change during an extended outro is worse than none (see the Neural tuner-mute evidence in Q6), so default to "arm and prompt".
- Idea: per-song MIDI/OSC "instant commands" out. What: a per-song list of PC/CC/Note/OSC messages sent when the daemon sees the song (or pedal patch) change: lights, a drummer's BeatBuddy/Soundbrenner, a bandmate's BandHelper/OnSong (which accept Song Select/PC to follow position), a DAW. Why: BandHelper, Boss PATCH MIDI (4 PC + 4 CC per patch) and Helix Command Center all do this; cover-band users wire lights from setlist apps (see Q8). Effort S (python-rtmidi; the daemon already tracks patch changes). Value medium (rises if the band adds lights or a MIDI metronome). Implement with the Helix-forum lessons: space PC and CC messages, de-duplicate on out-of-order selection, show 0/1-based PC numbers explicitly (Q2 findings).
- Idea: MIDI beat clock out at the song's tempo. What: emit MIDI clock (and start/stop at the two-bar tap) from the song tempo so a drummer's metronome or a BeatBuddy locks to the set. Why: BandHelper and Stage Traxx both offer beat clock/MTC out. Effort S. Value medium (drummer-dependent).
- Idea: cue-authoring ergonomics (better version of "record cues"). What: Stage Traxx-style global per-song offset (`[offset:ms]`) and "seek to timestamp" for every recorded cue list, plus a nudge command ("all cues 300 ms later"). Why: three Fractal users describe hand-coding timestamps as the pain. Effort S. Value medium.
- Idea: song-usage history and smart set building. What: aggregate recaps into times played, last played, average tapped-tempo drift, songs flagged off-level or tweaked repeatedly; expose "songs not played in N weeks" and "songs that misbehaved twice" to the set builder and to Claude. Why: OnSong Song Reporting, BandHelper smart lists and ratings. Effort S (the recap already logs songs played). Value medium.
- Idea: per-member notes and personal views. What: data fields for notes-per-member and a per-member transpose/capo view on the shared stage page (Q7), with a master copy the guitarist owns. Why: BandHelper's "personal versions" and OnSong Profiles ("capoed versions for guitarists"). Effort S–M. Value medium (only matters once bandmates view the stage page).
- Idea: run sheet with scheduled times. What: set-level entries for doors, set 1, break, set 2, last song, curfew, with alerts; feeds the set clock above. Why: OnSong Moments. Effort S. Value medium.

## Q2. Backing-track / playback rigs: click, count-in, cues, vamps, transitions, MIDI out, tempo changes

### Takeaway
Worship-oriented playback rigs (MultiTracks Playback, Loop Community Prime) run the song: click and spoken section cues on their own bus, infinite "click sections" to cover spontaneous gaps, loop/jump-to-section on demand, pads between songs, and timeline MIDI cues (PC/CC/Note) to switch patches on guitar gear; Ableton supplies the vocabulary for quantized vamps (Follow Actions, Launch Quantization, Legato). Line 6 now ships the whole model inside a modeler (Helix Stadium "Showcase": song timeline with flags that recall presets/snapshots, looper and MIDI, tempo-change flags, stem splitting). g3xn already has the clock, part map and timed cues; the missing pieces are spoken cues generated from the part map, count-in/vamp click semantics, quantized section loops on the ghost band, and tempo maps per song.

### Cited Findings
- Playback 7.7.0: "Playback users can now add a 'Click Section' at any point in a song" (beginning, end or middle) to cover "spontaneous moments or gaps"; a click section loops infinitely by default (toggle via the ∞ icon), is 2 or 4 bars long (per-song setting), requires a Premium seat and the built-in click — [MultiTracks help: click sections](https://helpcenter.multitracks.com/en/articles/6813885-adding-click-sections-within-a-song-in-playback) [official-docs]
- Playback help articles exist for "Guide Settings for Specific Song Sections", routing "Click & Guide to Separate Busses", AutoPan (click one side, tracks the other), custom/named arrangements, section trimming and renaming, Song Pads, setlists, MIDI clock out, tap tempo and per-song key/tempo change (titles only; contents not opened) — [Guide per section](https://helpcenter.multitracks.com/en/articles/12497923-guide-settings-for-specific-song-sections); [Click/guide busses](https://helpcenter.multitracks.com/en/articles/5224107-how-to-route-click-guide-to-separate-busses-in-playback); [Custom arrangements](https://helpcenter.multitracks.com/en/articles/6437439-how-to-create-custom-arrangements-in-playback); [MIDI clock out](https://helpcenter.multitracks.com/en/articles/5524066-how-to-send-midi-clock-out-of-playback); [Key and tempo](https://helpcenter.multitracks.com/en/articles/4520655-how-to-change-the-key-and-tempo-of-a-song-in-playback) [official-docs]

### Inferences
- Idea: spoken section cues generated from the part map. What: local TTS ("chorus in 2, 3, 4", "solo next", "last chorus") scheduled one bar before each part boundary on the song clock, routed to the guitarist's headphone/IEM output on the interface (never the PA); optional per-song custom cue text; voice-editable via Claude ("add a cue before the bridge: watch the stop"). Why: Prime generates spoken cues from typed text and ships section cues with every track; Playback has per-section guide settings. Effort S–M (piper or OS TTS; the clock and part map exist). Value medium-high: it is the one backing-track feature that works with a live band and no tracks.
- Idea: count-in and vamp click. What: a 1–2 bar count-in before the ghost band or on "start the clock", an optional click into the headphone bus for intros only, and a Playback-style "click section" that loops 2/4 bars until "go" to cover talk-ups and spontaneous gaps. Why: Playback 7.7.0 added exactly this for "spontaneous moments or gaps". Effort S. Value medium.
- Idea: quantized loop/jump on the ghost band. What: "vamp this part" loops the part's bar range at the current playback speed; "go" exits at end of section / after 1 bar / after 2 bars (user default); "jump to solo" lands on a downbeat; the clock and lyric scroll follow the jump (Ableton's Linked follow action + Launch Quantization semantics, Prime's loop/jump on demand). Effort M (sample-accurate loop points at variable speed; part map must carry bar boundaries). Value medium-high for cover sets with stretched solos and sing-alongs.
- Idea: per-song tempo map. What: parts may carry a tempo and time signature (Helix Stadium Time flags); the song clock, lyric timing, cue times and the delay-time edits the daemon writes follow the map. Why: Fractal's most-reacted setlist request (Q3) and Stadium's Time flags; cover sets contain tempo changes. Effort M. Value medium.
- Idea: pads/drone between songs in the next song's key. What: play a pad through the interface (or the pedal's AUX IN, which mixes into the outputs) during changeovers, keyed from the next song. Why: Prime Tonic Pads, Playback Song Pads. Effort S–M. Value low for pop/rock covers (worship-centric); note only.
- Validation: automatic preset/snapshot recall from a song timeline is now a shipping modeler feature (Showcase flags); g3xn's timed cues are the same idea. The better version is making full patch switches first-class cues in the part map (if not already) and firing them from the clock with the "arm and prompt" rule when the clock is uncertain (Q4).
- Pattern for any new MIDI out (from Q2 and Q1 ideas): space PC/CC by a few ms, suppress duplicate messages when songs are selected out of order, and display PC numbers in both 0- and 1-based form; these three are the documented failure modes.

### Gaps
- Playback count-in configuration (bars, subdivision, accents) and the contents of the guide-per-section, custom-arrangement and MIDI-clock articles were not opened; "Tempo Flex"/tempo ramps were not found in any tool.
- What Prime's factory cue vocals actually say, Prime's MIDI-out message types and auto-advance behaviour, and the jump-timing options remain unconfirmed (aggregator only).
- Ableton Launch Quantization value list, scene tempo fields and Link start/stop sync were not captured; no documented Ableton-to-Helix/Kemper/QC per-section workflow beyond generic forum threads.
- Boss RC-505/RC-600, Line 6 HX looper gig workflows, Link-enabled metronome apps and ShowOne's official page were not researched.
- Performer demand evidence exists only for Link venue failures and DAW-MIDI timing; none for click, guide, pads, vamps or transitions beyond vendor copy.

## Q3. Guitar modeler ecosystems: setlist / gig / performance features, and what users say is missing

### Takeaway
Across Helix, Quad Cortex, Kemper, Fractal, Boss and HeadRush the live model is one preset per song with scenes/snapshots per section, setlists (as copies, which users want replaced by pointers), footswitch label views, per-preset or per-snapshot tempo, global EQ for the room, tails/spillover, a tuner that mutes, instant MIDI commands on preset load, and cloud preset sharing. The most-reacted open request found is Fractal's "BPM per song in the setlist" (Nov 2022, 19 and 27 reactions, "under consideration"), followed by per-section tempo, key per song, gapless switching, setlists-as-pointers, and gig views that stay put. g3xn already covers pointers, gig lock, state-aware display and per-song tempo/key; the computer side can add venue EQ profiles, a level-matching routine, tuner-mute automation and a footswitch label view, but cannot fix the pedal's lack of spillover across patch changes.

### Cited Findings

## Q4. Lyrics/teleprompter tools that follow the performer: what they do when the follow is uncertain

### Takeaway
No product was found that positions lyrics or chords by listening to a whole band; everything that listens (PromptSmart, VoicePrompter, Speakflow, Antescofo, Cadenza) follows one voice or one instrument in a quiet room with a close mic. Their UX when uncertain is the useful part: hold at the last matched position and resume, re-localize across the whole script including backwards, keep a timed/manual mode underneath as an explicit fallback, show live where the follower thinks you are, converge tempo from the written value, and never prune the search window so hard that one error loses you for good. g3xn's tapped clock plus voice nudges is already the fallback these products rely on.

## Q7. Shared "current song", tempo and lyrics across band members' devices

### Takeaway
Every band app syncs on a local network with a leader/follower model: BandHelper (iOS peer-to-peer without a router; Android/mixed on the same Wi-Fi; broadcasts song selection, page position, highlights, set changes, completed songs and chat with ~0.5 s delay; up to 15 followers), OnSong Connect (Wi-Fi; stream current song/set and control members), Stage Traxx Network Sessions (host streams playback state, song, lyrics, position and a 20-song queue; recommends a dedicated 5 GHz router on stage), LivePrompter LP Connect (unacknowledged UDP broadcast on port 3000 plus a later heartbeat), MobileSheets (Bluetooth/Wi-Fi with reconnect complaints). Tempo sharing is Ableton Link, which fails on venue Wi-Fi with client isolation. g3xn already pushes state to a phone; the delta is multi-client fan-out with per-member views, a join flow that avoids venue Wi-Fi, and optional Link/MIDI-clock tempo.

### Cited Findings
- BandHelper Live Sharing: iOS-to-iOS works "without a router or an Internet connection"; Android or mixed needs all devices on one Wi-Fi network (no Internet required: portable router, laptop ad hoc, or hotspot); lead uses "Broadcast Screen" or "Broadcast Actions", followers "Display Screen From"/"Follow Actions From", "Auto-Accept Connects", "Rebroadcast Received Actions" to chain; synced: song selections, layout gestures, remote-control messages, page positions, lyrics highlights, set list selections and changes, completed songs, chat messages ("Speak Chat Messages"), account syncing; not synced: starting functions like autoscroll; action sharing has "about a half-second delay" and "is not intended for situations that require precise timing" ("Delay Actions" compensates); screen sharing has a "1-3 second transmission delay"; iOS stops advertising after a few minutes; iOS 13+ needs Local Network permission; "Some routers block traffic between devices"; backgrounding may disconnect — [BandHelper linking devices](https://www.bandhelper.com/tutorials/linking_devices.html) [official-docs]; up to 15 followers — [BandHelper features](https://www.bandhelper.com/main/features.html) [official-docs]
- OnSong Connect (Premium): "a communications layer... to control or to be controlled by other compatible apps on your local network using WiFi"; Beaming (send songs/sets), Streaming ("send your current songs and set, but also control their device", keeps "everyone... on the same page"), Profiles (e.g. "capoed versions for guitarists") — [OnSong Connect](https://onsongapp.com/docs/features/connect/) [official-docs]; networking and MIDI stop when backgrounded unless "Run In Background" — [OnSong hands-free](https://onsongapp.com/docs/features/hands-free/) [unconfirmed snippet]
- Stage Traxx 3.8 Network Sessions: host turns on "Host Session", clients "Join Session"; clients see the host's lyrics, current title, playback time and a waveform with the host's position, plus the queue of up to 20 upcoming songs; clients can autoscroll and send the MIDI defined in lyrics; local lyrics matched by title and artist; Wi-Fi with Bluetooth also enabled; full version in-app purchase; "a dedicated Wi-Fi network is recommended, preferably on 5 GHz with its own router placed on stage"; many audience devices add interference; the session is disabled in the background when no clients are connected; PDF sending can be turned off if switching is slow — [Stage Traxx network sessions](https://stagetraxx.com/user-guide/network-sessions/) [official-docs]
- LivePrompter LP Connect: master broadcasts song changes (by file name), play/pause, scroll up/down and reset; all devices on the same wireless network ("bring a Wi-Fi router to the gig"); "fire-and-forget" with no acknowledgment; "wifi networks can be finicky"; server port 3000, automatic discovery; slave options incl. "Change Setlist to All Songs if needed"; two masters with the same name "will mess everything up"; opening Settings disconnects — [LivePrompter LP Connect](https://www.liveprompter.com/help/help-lp2/advanced/lp-connect-master-slave-networking/) [official-docs]; 1.5.2 "added a heartbeat mechanism to detect and correct dropped connections" — [LivePrompter version history](https://www.liveprompter.com/help/help-mobile/advanced-help-v2/version-history/) [unconfirmed snippet]
- MobileSheets Connect Tablets: Bluetooth pairing or Wi-Fi; "New Leader"/"Join Group"; leader advertises 120 s; options to turn pages and load songs/setlists on followers; staff say Wi-Fi is most reliable; users report reconnect failures fixed by forgetting the pairing — [MobileSheets forum 11000](https://zubersoft.com/mobilesheets/forum/thread-11000.html); [MobileSheets forum 5236](https://www.zubersoft.com/mobilesheets/forum/thread-5236.html) [unconfirmed snippet]; recurring requests to link tablets — [MobileSheets forum 10513](https://www.zubersoft.com/mobilesheets/forum/thread-10513.html) [unconfirmed snippet]
- Ableton Link needs same-network visibility; venue/guest networks often block it; client isolation and mDNS discovery are the failure points; Wi-Fi drops "during live sets"; hardwire or ad hoc recommended — [OnSong Ableton Link](https://www.onsongapp.com/docs/features/ableton-link) [official-docs]; [Ableton forum](https://forum.ableton.com/viewtopic.php?p=1817505) [unconfirmed snippet]; Link runs over Wi-Fi or Ethernet — [Engine DJ community](https://community.enginedj.com/t/does-ableton-link-only-work-over-wifi/47339) [unconfirmed snippet]; a hardware Link bridge exists (Circuit Happy "The Missing Link") — [Waveform review](https://waveformmagazine.com/waveform-reviews/circuit-happy-the-missing-link/) [article]

### Inferences
- Idea: band follow pages. What: bandmates open a URL on their phones showing the live stage state (current/next song, key, tempo with a visual beat, tuning, part, lyrics/chords, their own notes); read-only by default with a few buttons (messages, "I'm ready"); fan-out over WebSocket/SSE from the daemon, which already pushes to the guitarist's phone. Join flow: QR code with a short-lived token; network: the laptop's hotspot or a travel router on stage (Stage Traxx advice), or Tailscale for bandmates who install it; keep last-known state and a stale badge on disconnect, auto-reconnect, and a heartbeat (LivePrompter's 1.5.2 lesson). Effort M (multi-client state, tokens, per-member view; a new page would be needed). Value high: it is what the Kemper and MobileSheets users are hand-assembling.
- Idea: MIDI Song Select / PC out and in for third-party apps. What: emit Song Select/PC on song change so a bandmate's BandHelper/OnSong follows position; accept Song Select so a bandmate's app can drive the stage. Effort S. Value medium.
- Idea: tempo sharing. What: Ableton Link via aalink (GPL-3.0 — a licensing decision for the suite; LinkPython-extern as the alternative, license not checked) so Link-capable metronome apps lock to the song tempo, and MIDI clock over a cable for drummers with hardware metronomes; only on a stage LAN with mDNS, never venue Wi-Fi. Effort S–M. Value medium (drummer-dependent).
- Idea: reliability conventions. What: half-second class latency is acceptable for song/part sync but not for cues (BandHelper's own caveat), so cues stay local to the daemon; "Delay Actions"-style offsets per device; auto-accept connects during the show; disable sleep/backgrounding warnings on the phone page. Effort S. Value medium.
