## File structure

| File | What changes |
|---|---|
| g3xn/models.py | New. The two pedal models and the mode (read, switch) |
| g3xn/catalog.py | One catalog per model; DSP budget per model |
| g3xn/patch.py | Patch carries its model: size, target, chain rule, empty PPRM, catalog |
| g3xn/pedal.py | Pick the port by the `44` reply, refuse the wrong pedal, per-model scratch and state, length-only read-back, push verifies on unproven models, no screen on untested models |
| g3xn/sim.py | VirtualPedal(model=...) answers as either pedal |
| g3xn/backups.py | Raw compare up to the PTCF length |
| g3xn/service.py | Per-model backup folder; `mode()`; status reports the model's limits |
| g3xn/mcp_server.py | `pedal_mode` tool; instructions and tool text without G3Xn-only numbers |
| g3xn/cli.py | `g3xn mode` |
| g3xn/data/effects_b1xfour.json | New. The B1X catalog |
| tools/build_catalog.py | Skip built-ins the templates lack; take the model's continuation rule |
| tests/test_b1xfour.py | New. Mode, detection, patches, catalog, sim, push fallback, MCP |
| skills/zoom-g3xn/SKILL.md | A bass mode section |

## Deviations

- The gate is `unittest discover`, not pytest: pytest is not installed in this repo.
- The new tests live in one file, tests/test_b1xfour.py, committed with task 5.
- Every existing test module imports tests/pin_mode.py, so the suite runs in G3Xn mode even when this computer is in bass mode.
- In bass mode the MCP server opens the B1X FOUR directly instead of going through the desktop app's daemon. The daemon drives only the G3Xn, so the app can stay open on the guitar pedal. `Pedal.open` skips a Zoom port another program holds instead of failing.
- The daemon is pinned to the G3Xn (`model="g3xn"`).
- The plugin version is bumped to 0.2.0, so the installed plugin picks the bass tools up from GitHub.
- Hardware run on 2026-11-16 (B1X FOUR, firmware 2.00, scratch slot 50): an offline-built bass patch, live knob, on/off, volume and name edits, save to a slot, screen text and tuner on/off all work. 235 of 235 knob edits landed. A read about 0.3 s after a patch change can be 30 to 45 ms behind, so `push` reads again before it rewrites the slot. The flag is now `check_live_edits`, and `has_screen` is on for the B1X FOUR. The pedal does not copy live edits into the stored slot (autosave is off or absent). Tempo was not sent: it is one master setting with no read command, so the old value cannot be put back.
