# B1X FOUR support: plan (#1)

Spec: docs/specs/2026-11-15-b1x-four-design.md

## File structure

| File | What changes |
|---|---|
| g3xn/models.py | New. The two pedal models and the mode (read, switch) |
| g3xn/catalog.py | One catalog per model; DSP budget per model |
| g3xn/patch.py | Patch carries its model: size, target, chain rule, empty PPRM, catalog |
| g3xn/pedal.py | Pick the port by the `44` reply, refuse the wrong pedal, per-model scratch and state, length-only read-back, push verifies on unproven models, no screen on untested models |
| g3xn/sim.py | VirtualPedal(model=...) answers as either pedal |
| g3xn/backups.py | Raw compare up to the PTCF length |
| g3xn/service.py | Per-model backup folder; `mode()`; status reports the model's limits |
| g3xn/mcp_server.py | `pedal_mode` tool; instructions and tool text without G3Xn-only numbers |
| g3xn/cli.py | `g3xn mode` |
| g3xn/data/effects_b1xfour.json | New. The B1X catalog |
| tools/build_catalog.py | Skip built-ins the templates lack; take the model's continuation rule |
| tests/test_b1xfour.py | New. Mode, detection, patches, catalog, sim, push fallback, MCP |
| skills/zoom-g3xn/SKILL.md | A bass mode section |
