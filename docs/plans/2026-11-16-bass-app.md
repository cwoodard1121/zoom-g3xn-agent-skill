# Plan: bass mode in the Electron app, and a first release (#3)

Spec: docs/specs/2026-11-16-bass-app-design.md

## File structure

| File | Purpose |
|---|---|
| g3xn/daemon.py | `--pedal`, `run_modes`, `POST /api/mode`, `model` and `modes` in status, per-pedal files, frozen-build paths |
| g3xn/models.py | Per-pedal history, gigs and guitars paths, `Model.app_view()` |
| g3xn/desktop.py | The pywebview window uses `run_modes` too, no G3Xn pin |
| g3xn/mcp_server.py | Every tool goes through a running daemon, `pedal_mode` switches the app |
| g3xn/service.py, g3xn/cli.py | `mode` tells a running daemon |
| g3xn/chat.py | The frozen daemon starts its own MCP server |
| g3xn/frozen_main.py | Entry point of the frozen daemon (daemon or MCP server) |
| app/src/* | Limits from `status.model`, pedal name, Guitar / Bass switch, pedal screen numbers |
| desktop/main.js | Bundled daemon first, `--bass`, `--guitar` |
| desktop/build.js, desktop/release.js, desktop/package.json | Local build without a baked path, `npm run release` |
| tests/test_bass_app.py | Mode switch over HTTP, per-pedal files, MCP through the daemon |
| README.md, skills/zoom-g3xn/SKILL.md, plugin files, pyproject.toml | Docs and version 0.3.0 |

## Interface checklist

`POST /api/mode`: body `{"pedal": "g3xn"|"b1xfour"|alias}`. Reply `{"mode": key, "name": …, "restarting": true}`. 400 on an unknown key or a locked gig. Local requests and paired phones only, like every other route.
